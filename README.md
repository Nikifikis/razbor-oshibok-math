# Разбор — персональная работа над ошибками

Учитель создаёт ученика, получает личный код и назначает конкретные тему, уровень и навыки. Ребёнок видит только свои активные работы. Свободного каталога и переключения в 3.0 в ученическом режиме нет.

Проверка промежуточных ответов и самостоятельных примеров выполняется сервером. Кабинет показывает ошибки, подсказки и ответы по шагам. Новые тренировочные конструкции отличаются от присланных подтверждений; банк подтверждений не включён в приложение.

## Развёртывание на существующем сервере

1. Разместить проект в отдельном каталоге, например `/opt/razbor`, не заменяя TutorPro.
2. Выполнить `node scripts/setup-teacher.cjs`. Скрипт создаст настройки и закрытый файл `teacher-access.txt` с логином и паролем. Существующие настройки он не перезаписывает. Альтернатива — подготовить `.env` из `.env.example` со своим хешем пароля.
3. Проверить, что локальный порт 8020 свободен, и запустить `docker compose up -d --build`.
4. Добавить отдельный виртуальный хост Nginx, направленный на `127.0.0.1:8020`. Шаблон: `deploy/timeweb-nginx.example.conf`.
5. Подключить домен и HTTPS. Cookie входа имеет флаги Secure, HttpOnly и SameSite=Strict; для детей используется двухчасовой сеанс.
6. Войти в `/teacher.html`, создать учеников и персональные назначения. Передавать ребёнку только его код.

База: `data/razbor.sqlite`. Используйте согласованную резервную копию SQLite вместе с постоянным каталогом данных; не коммитьте базу, `.env` и пароли.

GitHub Pages публикует закрытую входную страницу и не запускает сервер. Если API не подключён, задания недоступны. Старые назначения без списка навыков также закрыты до нового назначения учителем.

`npm run check` проверяет код и математические преобразования; `npm run test:access` проверяет доступ, серверную проверку и отзыв назначений. Подробности: `docs/personal-access.md`.
